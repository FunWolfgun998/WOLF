Instruction scheduling

Code:
x = a*b+c/d

AST
Assing(x,+(*(a,b),/(c,d)))

Intermidiate abstrac assembly
load a -> r1
load b -> r2
mult r1,r2 -> r3
load c -> r4
load d -> r5
div r4,r5 -> r6
add r3,r6 -> r7
store r7 -> x

Each type of command (load, mult, div) have a latency that is the number of cycles to complete that particular command

Latecies for each command:
load = 3 cycles
mult = 2 cycles
div = 5 cycles
store = 2 cycles
add = 1 cycle

The total number of cycles for this example is:
3+3+2+3+3+5+1+2 = 22 cycles
Thanks to pipelining we can execute instruction in parallel -> start a new instruction in each cycle.
In our a case we use a single issue machine -> in each cycle we can start a new instruction BUT that must not depend form previous instructions.

(N. instr.)|start cycle|end cycle|instruction
(1) 1-3	load a -> r1
(2) 2-4	load b -> r2 => indipendent -> new instruction at new cycle
(3) 5-6	mult r1,r2 -> r3 => dependent of both => the compiler contruct the dependence graft where it takes the number of the instruction. The dependence graft is a inverted AST whre the link is based on the dependence from the upper instructios
(4) 6-8	load c -> r4
(5) 7-9	load d -> r5
(6) 10-14 div r4,r5 -> r6
(7) 15-15 add r3,r6 -> r7
(8) 16-17 store r7 -> x

From 22 thanks to pipelining we end with 17 cycles need it to execute this line of code. This appand in 17 cycles if we consiced that every value is store in cache and not in memory. Bringing something from the memory takes hundreds of cycles instad of the cache. this can slow a lot the process. 
The compiler try make an extimate but is not 100% right. 
To do that it would use the instruction scheduler where based of de independance of each instruction decides which instruction it should do first. Longher and independent instructions will be executed at the beginning.
(N. instr.)|start cycle|end cycle|instruction
(1) 1|3	load a -> r1
(2) 2|4	load b -> r2
(4) 3|5	load c -> Xr4->r3
(5) 4|6	load d -> Xr5 ->r4
(3) 5|6	mult r1,r2 -> r5
(6) 7|11 div r3,r4 -> r6
(7) 12|12 add r5,r6 -> r7
(8) 13|14 store r7 -> x
Now thanks to instruction scheduling we need only 14 cycles.
But the fact that we use less cycles dosen't mean that we use less registes. This in facts uses more registers at the same time. In the first (no instruction scheduling) the peak register pressure is 3 in the 5th instruction. In the second (with instruction scheduling) the peak register pressure is 4 in the 4th instruction.

So in the first case with pipeline we have 17 cycles and we need 3 physical registers and in the second we have 14 cycles and we need 4 physical registers
So what the compiler should do?
It depend based on the architecture/machine, in the number of registers. any realistic formulation of instruction scheduling is NP-complete.
NP-complete problem is a class of problem that are equivalent to each other, that have no polynomial time solution, so no polynomial time algorithm that create always the best optimal solution.
The algorithm that we have is exponential/factorial takes lots of time, therfore is not practical/possible to use.
Compilers use certain heuristics, something that is not optimal but something similar to the optimal solution in most cases.
